# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

CLI (`src/gp2midi.py`) that converts Guitar Pro tab tracks into one MIDI file per track. It reads the GPIF XML format used by Guitar Pro 6/7/8: `.gp` (GP8 zip, score at `Content/score.gpif`), `.gpx` (GP6 BCFZ-compressed BCFS container holding `score.gpif`; the reader is picked from the file's first bytes, not the extension, and zip `.gpx` files are accepted too), or raw `.gpif`/`.xml`; and GP3/GP4/GP5 binary files (`.gp3` / `.gp4` / `.gp5`) through PyGuitarPro (in progress, see `docs/formats.md`). Dependencies: `mido`, and `pyguitarpro` for GP3–5 files only (the `gpif` package imports it lazily).

## Commands

```bash
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt   # setup
pip install -e '/path/to/gp-2-midi[gp5]'                             # optional: use the gpif library from another project ([gp5]: GP3-5 support)
.venv/bin/pip install -r requirements-dev.txt                       # test deps (pytest)
.venv/bin/python -m pytest test                                       # run all tests
.venv/bin/python -m pytest test/test_parsers.py -k rhythms            # run a subset
.venv/bin/python src/gp2midi.py in/song.gp        # writes <stem>_track<id>_<name>.mid next to input
.venv/bin/python src/gp2midi.py in/song.gp -o out/ --all-tracks --velocity 100
.venv/bin/python src/gp2midi.py in/song.gp -o out/ --no-humanize     # exact score, no random / strum variation
.venv/bin/python src/gp2midi.py in/song.gp5 -o out/   # GP3/4/5 files too (PyGuitarPro)
.venv/bin/python src/gpinfo.py                 # list fretted tracks (strings, tuning, capo) of every file in in/
.venv/bin/python src/gpinfo.py in/x.gp --json  # same for given files/dirs, as JSON
```

Tests live in `test/` (pytest; `conftest.py` puts `src/` on `sys.path` and provides `gpif(body)`, which wraps XML fragments in a `<GPIF>` root):
Test files mirror the modules:
- `test_parsers.py` — each `parse_*` function (`gpif/readers/gpif_xml.py`), using small inline XML fragments, including the GP8 vs GP6 element paths and defaults.
- `test_score.py` — `track_bars` on hand-built `Score`s (`gpif/score.py`).
- `test_model.py` — `element` / `properties` / `property_value` and the equality rules (`gpif/model.py`).
- `test_mixins.py` — the shared reader mixins (`gpif/readers/mixins.py`): track classification, rhythm, bend curve, harmonic, dynamics, `ScoreBuilder`, and how the content mixins compose them.
- `test_gp345.py` — the GP3/4/5 readers (`gpif/readers/gp345.py`): songs built in code with PyGuitarPro (`add_beat`, `new_song`), written to `tmp_path` as `.gp3` / `.gp4` / `.gp5` (`write_read`) and read back; parametrized over the versions. Never reads the GP3–5 files in `in/`.
- `test_theory.py` — `midi_pitch`, `pitch_name`, `tuning_label`, `harmonic_interval`, `harmonic_pitch` (`gpif/theory.py`).
- `test_gp2midi_bends.py`, `test_gp2midi_dynamics.py`, `test_gp2midi_hopo.py`, `test_gp2midi_mutes.py`, `test_gp2midi_vibrato_slides.py`, `test_gp2midi_grace.py`, `test_gp2midi_harmonics.py`, `test_gp2midi_channels.py`, `test_gp2midi_staves.py`, `test_gp2midi_humanize.py` — MIDI output helpers, plus end-to-end `track_to_midi` runs on a tiny score via `conftest.convert(tmp_path, note_list, dynamics=..., graces=..., chords=..., staff_of=..., beat_fields=..., track=..., rng=..., **options)` (builds a one-bar `Score` by hand; `staff_of` puts each beat on a staff, `beat_fields` gives each beat extra `Beat` fields such as `{'brush': 'up'}`), where `options` are `MidiOptions` fields (e.g. `hopo_overlap=20`). `convert` turns `humanize` off unless a test passes it; `rng=conftest.ScriptedRandom([3, -5])` scripts the random values humanize draws.
- `test_gpinfo.py` — `gpinfo.file_info` and `find_files` on a GP5 song built in code.
- `test_loading.py` — the readers (`gpif/readers/`): `reader_for`, each reader class, `load_gpif_xml` and `load_score` for zip, BCFS, BCFZ and raw XML. Contains test-only encoders (`BitWriter`, `bcfz_literals`, `bcfz_compress` with real back-references, `bcfs_container`) that build synthetic GP6 files. `FULL_SCORE_XML` is a small complete GPIF document (multi-staff, GP6-style and drum tracks, tempo change, brush, let ring, whammy, attribute-form tuplets and dots), written as `.gp`, compressed `.gpx` and raw XML by `write_full_score`. `test_all_input_files_load` loads every Guitar Pro file in `in/`, all formats, and skips when there are none.

When adding parser support (e.g. articulations), add fragment tests to `test_parsers.py`. To explore a feature first, read it from the model's raw XML (`note.element.find('LetRing')`, `beat.properties.get('Brush')`) before giving it a parsed field. There is no linter or build step. Also verify end-to-end by converting files from `in/` into `out/` and inspecting the output (e.g. load the `.mid` with `mido.MidiFile` and print messages). Check a GP8 `.gp` file, and also convert a `.gpx` when touching loading or note parsing, since GP6 files differ (BCFZ container, no `Midi` note property). `in/` holds the input tabs and is git-ignored (they may be copyrighted), as are `*.mid`, `out/` and `tmp/`. Unit tests must not depend on files in `in/`: the repo is public and ships none, so tests build their data in code (GPIF XML fragments; GP3–5 songs with PyGuitarPro). The only test that reads `in/` is `test_all_input_files_load`, a load check over whatever files are there, which skips when there are none.

### Inspecting raw GPIF XML

When adding parser support, grep the raw XML. Extract it into the git-ignored `tmp/`:

```bash
mkdir -p tmp
# GP7/GP8 .gp (zip): score is at Content/score.gpif
unzip -p in/song.gp Content/score.gpif > tmp/song.gpif
# Any format, including GP6 BCFZ .gpx (not a zip): use the project's loader
.venv/bin/python -c "import sys, xml.etree.ElementTree as ET; sys.path.insert(0, 'src'); import gpif; r = gpif.load_gpif_xml(sys.argv[1]); ET.indent(r); sys.stdout.write(ET.tostring(r, encoding='unicode'))" in/song.gpx > tmp/song.gpif
```

The loader route re-serialises the XML, so whitespace differs slightly from the original and CDATA sections become escaped text. The element structure is identical.

## Architecture

- `src/gpif/` — the reusable Guitar Pro library package, with no dependencies (no `mido`). `__init__.py` re-exports the public API (`__all__`), so callers write `from gpif import load_score` and never import the modules directly:
  - `readers/` — one reader class per file format (plan in `docs/formats.md`). `base.py`: `ScoreReader` (`name`, `extensions`, classmethod `sniff(head)`, `read(path) -> Score`). `containers.py`: container mixins with `sniff` and `load_xml(path)`: `ZipContainerMixin` (`PK`), `BcfsContainerMixin` (`BCFZ` / `BCFS`; private `_bcfz_decompress`, `_bcfs_files`), `RawXmlContainerMixin` (accepts anything, so tried last). `mixins.py`: logic shared by every format's content mixin, as mixins with static methods a format can override: `TrackClassificationMixin.classify_track(tuning, channel, instrument)` → `(is_drum, is_tab, is_fretted)` (plus `is_fretted_instrument`), `RhythmMixin.rhythm(beats, dots, tuplet)` → `Rhythm` (plus `TICKS_PER_BEAT`), `PitchEffectsMixin.bend_curve(points, position_scale, semitone_scale)` and `.harmonic(type, fret)` (plus `HARMONIC_TYPES`), `DynamicsMixin.dynamic_for_velocity` (GP velocities 15, 31 … 127 → `DYNAMICS` PPP … FFF). Also `ScoreBuilder`, not a mixin since readers are shared and stateless: a per-file collector handing out ids (`add_bar` / `add_voice` / `add_beat` / `add_note`, `rhythm_id` shares equal rhythms) and making the `Score`. `gpif_xml.py`: the GPIF parser, `GpifContentMixin` (the shared mixins + `read` = `self.parse_score(self.load_xml(path))`; one `parse_*` method per GPIF section, `parse_staff`, `bend_points`; the GPIF constants `NOTE_VALUE_BEATS`, `SLIDE_*`, `ACCENT_*`), the readers `Gp7Reader`, `Gp6Reader`, `GpifXmlReader` (each a container mixin + `GpifContentMixin` + `ScoreReader`), and the `parse_*` methods as module functions bound to one stateless `GpifContentMixin` (the public `gpif.parse_*` API). `registry.py`: `READERS` (one instance each, in sniff order), `reader_for(path)` (first reader whose `sniff` accepts the first `HEAD_BYTES`), `load_score(path)`, `load_gpif_xml(path)` (the XML root of a GPIF file). `gp345.py`: `PyGuitarProMixin` (`read` = `convert_song(guitarpro.parse(path))`; `convert_track` / `convert_measure` / `convert_beat` / `convert_note` / `convert_tempos` / `convert_info`, using the shared mixins and a per-read `ScoreBuilder` for ids; `guitarpro` imported lazily by `_guitarpro()`, with an ImportError naming the package), `gm_instrument(program)` (GM program → name for guitars / basses / banjo, else family; GP3–5 tracks name no instrument), and `Gp3Reader` / `Gp4Reader` / `Gp5Reader` (sniff the `FICHIER GUITAR PRO v3` / `v4` / `v5` header). Mapping: GP string 1 (highest) → model string `count − 1`; tuning reversed to lowest first; `offset` → capo; percussion → channel 9; voices whose beats are all empty are left out, an empty beat in a voice is a rest; tempo = song tempo, then mix-table changes at (bar, fraction of the bar); each note's velocity → `Note.dynamic`, the beat gets the most common. Articulations: accent / heavy accent, ghost, staccato, palm mute, dead, vibrato (note → slight; the beat's "wide vibrato" flag → wide on all its notes), slides (`SLIDES_IN` / `SLIDES_OUT`, out slides in GPIF's priority order), bends (points → `bend_curve(..., 12, 2)`: positions 0–12, values in quarter tones), harmonics (`convert_harmonic`: natural node = the fret, tapped = tapped fret − fret, artificial = pitch class + octave above the fretted note → `ARTIFICIAL_HARMONIC_NODES`, pinch / semi assumed `PINCH_HARMONIC_NODE` 7 / `SEMI_HARMONIC_NODE` 12), hammer-on / pull-off (GP flags the origin; `convert_beat` makes the next beat's note on that string in the same voice the destination, across bars, not ties, a rest breaks it; the pending strings travel in `convert_song`'s `hammers` dict), grace notes (`convert_grace`: a `GraceEffect` on a main note becomes a grace beat before the main beat, `on` if any is on-beat; hammer / slide / bend transitions → hopo pair / legato slide / bend up to the main fret), strokes (`stroke` → brush, `pickStroke` → pick stroke). What each version stores is listed at the top of the articulation tests in `test_gp345.py`. GP3–5 frets count from the capo (checked in step 6), so each note's `Note.midi` is set to tuning + capo + fret (`_pitch`). A new format is a reader class added to `READERS`.
  - `model.py` — the data types, frozen dataclasses with defaults on every field but ids: `Track` (`tuning` / `capo` are properties reading `staves[0]`), `Staff`, `MasterBar`, `Bar`, `Voice`, `Beat`, `Note`, `Harmonic`, `Rhythm`, `Tempo`, `ScoreInfo`. Lists stay lists. Build test objects with keywords (`Note(fret=5)`) and vary them with `dataclasses.replace`. Raw XML for anything not parsed: every object built from an XML element keeps it in `element` (None when built by hand; GP6 `Staff` and the `<Score>` tempo fallback have none), and `Note` / `Beat` have `properties` (every `<Property>` name → `property_value` text, '' for flags; a lazy `cached_property` read from `element`). `element` is excluded from `==` and `repr`.
  - `score.py` — the `Score` dataclass (`tracks`, `master_bars`, `bars`, `voices`, `beats`, `notes`, `rhythms`, `tempos`, `info`, `root` (GPIF XML), `source` (the non-GPIF reader's parsed object, e.g. the `guitarpro.Song`; not compared)) and `track_bars`. `parse_score(root)` (every `parse_*` section of a GPIF root) is in `readers/gpif_xml.py`.
  - `theory.py` — `midi_pitch`, `pitch_name`, `tuning_label` ("Standard", "Drop D", …), `harmonic_interval`, `harmonic_pitch`.

  Scripts in `src/` import it directly because the script's directory is on `sys.path`; `pyproject.toml` packages it (`gpif` and `gpif.readers`, not the scripts) for `pip install` elsewhere. A new public name goes in its module and in `__init__.py`'s imports and `__all__`.
- `src/gp2midi.py` — the MIDI CLI: `track_to_midi(track, score, output_path, options)`, tempo conversion, filename handling, `main`. All articulation settings live in the frozen `MidiOptions` dataclass (one field per CLI switch; defaults from the `DEFAULT_*` constants), which `main` builds from the clamped switch values and passes to `track_to_midi` and the helpers (`note_velocity`, `sounding_ticks`, `note_pitch_curve`). To add a setting: add a `DEFAULT_*` constant, a `MidiOptions` field, the argparse switch, and its clamp in `main`. `track_to_midi` runs in two passes: walk the score into a list of note occurrences (tick, duration, note, pitch, dynamic, bpm; tempo changes interleaved), then emit MIDI from that list. The second pass can look ahead, e.g. for a slide's target note.

GPIF is a normalized, ID-referenced XML document. Each `parse_*` function flattens one top-level section into a dict of model objects keyed by id, and `track_to_midi` walks the reference chain:

```
MasterBars (ordered, one per measure; holds time signature + space-separated Bar ids, one per track)
  → Bar → Voices (space-separated ids, played in parallel)
    → Voice → Beats (sequential)
      → Beat → Rhythm ref (duration) + Notes ids (chord) or Rest
        → Note → String/Fret properties + Tie
```

Key behaviors and assumptions:

- **Track ↔ bar mapping**: `MasterBar/Bars` holds one bar id per **staff** (tracks in document order; a GP8 piano track has two staves). `parse_tracks` gives each track `staves` (`[Staff(tuning, capo), ...]`; `track.tuning` / `track.capo` are staff 0's) and `bar_index` (its first staff's position in `Bars`), and `gpif.track_bars(score, track, staff=0)` returns that staff's bar in each master bar. `track_to_midi` merges all staves into one MIDI track; each occurrence records its `staff`, and per-string state (grace cut, slide targets, hammer-on overlap) is keyed by `string_key(occ)` = `(staff, string)`.
- **Pitch**: taken from the note's `Midi` property when present; otherwise tuning[string] + fret. GPIF string 0 is the *lowest* string, same order as the tuning list. String/Fret values live in `<String>`/`<Fret>` child elements (with `<Number>` as fallback).
- **Timing**: `TICKS_PER_BEAT = 480`. Rhythm durations apply dots (×1.5, ×1.75 for two) and tuplets (×den/num; a nested `SecondaryTuplet` multiplies in). GP6–8 files write them as attributes, `<AugmentationDot count="1"/>` and `<PrimaryTuplet num="3" den="2"/>`; the `<Enable>` / `<Num>` / `<Den>` child forms are also accepted. (Before 2026-10-20 only the child forms were read, so GPIF dots and tuplets were ignored.) Bar length always advances by the time signature, not by voice content, so partially-filled voices don't drift. Grace beats (`beat.grace`) take no bar time: a before-beat grace sounds just before the main beat, an on-beat one delays and shortens the main note; the previous note on the same string is shortened between the passes (fretted tracks only). `--grace-length` / `--grace-cut`.
- **Pitch effects** (bend, vibrato, slides): `parse_notes` gives `bend` = `[(fraction 0–1, semitones), ...]` or None (GPIF value 100 = 2 semitones), `vibrato`, `slide_in` and `slide_out`. `gp2midi.note_pitch_curve` adds them into one curve, which `curve_events` samples into pitchwheel messages. A note with no effect resets the wheel to 0 (tied continuations hold), repeated values are dropped, and RPN 0 (`--bend-range`, default 12) is sent only on tracks that use pitch bend. Shift/legato slides glide to the next note on the same string. Switches: `--vibrato-depth`, `--vibrato-rate`, `--slide-time`, `--slide-distance` (0 depth / time = off). Pitch bend is channel-wide, so an effect on one note of a chord moves all of it, unless `--channel-per-string` is on. Details in `docs/articulations.md`.
- **Velocity**: from the note's `dynamic` if set (GP3–5 notes each have one), else the beat's `dynamic` (PPP 16 … MF 80 … FFF 127 by default; `--dynamic-velocity PPP:16,PP:32,...` / `MidiOptions.dynamic_velocity`, parsed by `parse_dynamic_velocity`, levels not given keep `DYNAMIC_VELOCITY`) plus note `accent` (+16 / heavy +32) and `ghost` (−32), in `gp2midi.note_velocity`. `hopo_dest` notes (hammer-on/pull-off) are softer by `--hopo-cut` (default 16). `--velocity N` replaces all of this with a fixed value. `palm_muted` and `dead` notes are softer by `--palm-mute-cut` (8) / `--dead-note-cut` (16). Between the passes, `palm_mute_chords` palm mutes every note struck at an onset (tick, staff) where one is palm muted (not ties or dead notes; `--no-palm-mute-chords` keeps the marks per note). Sounding length comes from `gp2midi.sounding_ticks`: `staccato` halves it, `palm_muted` scales it by `--palm-mute-length` (0.5), `dead` caps it at `--dead-note-length` ticks (30); the shortest wins and a tie continuation still extends it. `--hopo-overlap TICKS` (default 0) holds a hammer-on/pull-off origin note into its destination on the same string, via `last_on_string` in `track_to_midi`. Details in `docs/articulations.md`.
- **Harmonics**: `parse_notes` gives `harmonic` (`Harmonic(type, fret)` or None). GP8's `Midi` value is the fretted pitch even for harmonics, so `gpif.harmonic_pitch` calculates the sounding pitch from `harmonic_interval(fret)` (the n-th partial at a string node): natural harmonics from the open string (the fretted pitch minus the fret, so a capo counts), the other types from the fretted pitch. The first pass uses it in place of the fretted pitch; a semi harmonic adds a second, softer occurrence. `--no-harmonics` / `--harmonic-cut`.
- **Channels**: one channel per track (the track's channel, 9 for drums). `--channel-per-string` puts each string on its own channel (`gp2midi.string_channels`: highest string on channel index 0, skipping 9) so pitch bend is per string; drum tracks, tracks without a tuning, tracks with more than 15 strings and multi-staff tracks keep one channel. `--mpe` (`MidiOptions.mpe`) uses the same per-string layout as an MPE lower zone: strings on `MPE_MEMBER_CHANNELS` (indexes 1–15, channel 10 included), and in the header `mpe_configuration` (RPN 6) and the program change on manager channel index 0, plus RPN 0 on every member channel; single-channel tracks get no MPE header. Each struck note's channel also gets CC74 (MPE timbre) before its note-on: `--palm-mute-timbre` (127) if palm muted, else `--open-timbre` (0), repeats removed by `drop_redundant_timbre`. Inside `track_to_midi`, `note_channel(note)` gives each note's channel, and ties, the wheel-repeat filter, RPN 0 and the final wheel reset all work per channel.
- **Ties**: a tie-destination note moves the earlier `note_off` for the same pitch (on the same channel) later instead of emitting a new note.
- **Events** are collected as `(abs_tick, sort_key, msg)`, sorted with `SK_OFF` (note_off, tempo) < `SK_RESET` < `SK_BEND` < `SK_ON` at equal ticks, then converted to delta times.
- **Humanize** (`--humanize`, on by default; `--no-humanize` gives the exact score): random values come from `track_to_midi`'s `rng` argument, by default `gp2midi.track_rng` (a `random.Random` seeded from `--seed` and the track id, so runs are reproducible). Humanize code only calls `rng.randint`, in a fixed order, so tests can script the values. Velocity: each onset tick draws one offset in ±`--velocity-spread` (default 5) the first time pass 2 meets a struck note there; `note_velocity(..., offset)` adds it to the dynamic's velocity before the accent / ghost / cut adjustments, so every note of a chord moves alike. No draw with `--velocity`, spread 0 or for tied continuations. Pick direction (fretted tracks): `picked_onsets` lists the picked onset ticks (not ties, hammer-on/pull-off or legato-slide destinations, or grace notes) with any scored `beat.pick_stroke`; `stroke_directions(onsets, bar_starts)` gives each the scored stroke; else, by its place in the beat, on the beat / 1st and 3rd sixteenth down and on the 'and' / 2nd and 4th sixteenth up (sixteenth grid for a beat with an onset between the eighths); off both grids (triplets), the opposite of the previous one when at most an eighth (`ALTERNATE_PICK_TICKS`) after it, else down. Strum: `strum_delays` delays each picked chord note by `--strum-time` ms (default 6) per string from the first struck string (lowest on a downstroke, highest on an upstroke), per (tick, staff); a beat marked as a brush or arpeggio (`Beat.brush` / `Beat.arpeggio`; `beat_stroke` picks arpeggio > brush > pick stroke) sets the direction and uses `--brush-time` (15) / `--arpeggio-time` (40) instead; in pass 2 the note-on moves, the note-off stays (delay capped below the sounding length), and pitch-wheel events move with the note only with `--channel-per-string`. Plan and status in `docs/humanize.md`.
- **Tempo**: from `MasterTrack/Automations` (falls back to `Score/Tempo`); GP3–5: the song tempo plus mix-table changes. Only changes at bar position 0 are applied. **Known bug, left as is by the user's choice (2026-10-20):** the tempo loop in `track_to_midi` only moves past a change at position 0, so a mid-bar change also blocks every later change. E.g. one sample file with a change at bar 5, position 0.125, stays at 76 BPM for the rest of the song. 21 mid-bar changes in the GPIF files in `in/`; details in `docs/formats.md`, decision 3.
- `src/gpinfo.py` — metadata CLI: lists each file's fretted tracks with string count, tuning (note names plus a name such as "Drop D" from `gpif.tuning_label`) and capo, for every format (`GP_SUFFIXES` picks the files in a directory).
- **Track selection**: by default only "tab" tracks (have a tuning and channel ≠ 9) are converted; `--all-tracks` includes the rest. GP8 gives vocal, keyboard and orchestral tracks a tuning too, so `is_tab` is broader than "fretted": `parse_tracks` also returns `instrument` (GP8 `InstrumentSet/Type`, e.g. `electricGuitar`; GP6 `Instrument@ref`, e.g. `e-gtr6`) and `is_fretted` (a tab track whose instrument matches `is_fretted_instrument`, or any tab track when no instrument is named), plus `capo`.
- Several fields have GP8 vs GP6/7 XML paths (tuning, program, channel) — `parse_tracks` tries the GP8 path first and falls back.
